声音设计余量电鼓

先按事件分类，不按音色分类

游戏音效的最小单位是事件：玩家点了什么、打中了什么、踩到了什么。先列事件表，写清触发条件、同时可能响几条、一分钟会重复几次，再决定做几条变体。只做一条，玩家听十次就腻；做十条，包体和维护成本一起涨。判断标准是重复频率，不是音色好不好听。

长度与峰值按事件定

事件常见长度变体关键处理
UI 点击60–200 毫秒2–3 条起音清楚，尾音短
奖励、升级1–3 秒1–2 条句法完整，可留尾
武器、命中200–600 毫秒3–5 条起音硬，低频收住
脚步100–300 毫秒4–8 条与地面材质配套
环境层20–60 秒循环1–2 条无缝，低频留余量

表里的长度是起点，不是标准。真正的上限由同屏叠加决定：十个命中同时响，单条再干净也会糊。峰值留 3–6 dB 余量，给引擎里的总线压缩和音乐留位置。

从素材到引擎的顺序

交 48 kHz、24 bit WAV 干声，循环另附无缝版与循环点位置。先做干声，不加混响；混响进引擎再做，否则同一个音效换到洞穴里就带着房间味。统一峰值与起点，切掉首尾多余静音，只留五到十毫秒防爆音。变体不要只随机音高，改起音、尾音和一点长度，听感才不会像玩具。循环音效首尾各留同样长的尾巴，交叉淡化后再进 Wwise 或 FMOD。命名按事件、材质、序号写，程序照表就能挂上。导入后先单独听，再叠对白、音乐和环境试三次。

验收要在游戏里听

  • 同一事件连发十次，没有一条像复读
  • 最响的命中不盖过对白与音乐
  • 快速点击 UI，声音不糊成一片
  • 脚步换地面时没有爆音
  • 3D 移动时近处不炸、远处不凭空消失
  • 循环接缝听不出来
  • 文件名与事件表一一对应
  • 包体在预算内

失败模式

把混响烘进文件，换场景就脏；变体只做音高随机，听感像玩具；峰值顶到零，叠加后削波；UI 音效拖到一秒，连点变噪音；环境循环只有十秒，玩家很快听出周期；命名靠 final2，程序找不到；音效和对白同频段，战斗时听不清台词；只交大文件，移动端包体超标。

在库中听例子

fanfare 01 0C10:02一秒八的 fanfare，十九个音，可听奖励提示怎样短到不打断操作详情VictoryC10:06六秒的胜利短曲，句法完整，适合对照「提示」与「过场」的长度差别详情selectC10:04四秒半的选单音，起音清楚，可参考 UI 音效的收尾详情creepyloop v2 aC10:57五十七秒、三十九个音的循环，留白多，可作环境底噪层的参照详情

每首均来自 MIDI曲库，行内徽标为许可档位（C1 可商用 / C2 非商业 / C3 仅学习研究）。
